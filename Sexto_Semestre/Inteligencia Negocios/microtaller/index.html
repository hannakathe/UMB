🧩 Identificación del problema

¿Qué situación busca solucionar este microtaller?

📌 Situación actual

La biblioteca lleva el control de préstamos en cuadernos y hojas sueltas. Con decenas de préstamos al mes, este registro manual genera problemas:

  • ❓ No se sabe con certeza cuántos ejemplares hay disponibles de un libro sin revisar los estantes.
  • ⏰ Los retrasos en las devoluciones se detectan tarde o nunca, porque nadie cruza fechas límite con la fecha actual.
  • 📈 No hay información sobre qué libros y categorías se piden más, así que las compras de nuevos ejemplares se deciden sin datos.
  • 🔍 Buscar el historial de un usuario o de un libro toma mucho tiempo.

🎯 Objetivo de la solución

Construir una aplicación web sencilla que permita:

  • 📝 Registrar préstamos (libro, usuario, fecha y plazo) validando que haya ejemplares disponibles.
  • ↩️ Registrar devoluciones y marcar automáticamente si fueron a tiempo o con retraso.
  • 📊 Ver un dashboard con indicadores de libros prestados, disponibles, más consultados y retrasos.
  • 💾 Guardar y exportar la base de datos en CSV para análisis posterior.

Preguntas que se responden con los datos: ¿Cuántos libros están prestados hoy? ¿Cuántos ejemplares quedan disponibles? ¿Qué libros se consultan más? ¿Qué porcentaje de préstamos se devuelve tarde?

🗃️ Datos

Base ficticia: títulos, usuarios y préstamos registrados entre agosto y noviembre de 2026.

🛠️ Tecnología

HTML + CSS + JavaScript en un solo archivo. Gráficas en SVG propias, sin librerías externas. Datos guardados en el navegador (localStorage).

📏 Regla de negocio

Plazo estándar de préstamo: 14 días. Un préstamo está retrasado si no se ha devuelto y la fecha actual supera su fecha límite.
